# PRD Index

One entry per PRD in this directory. Before writing a new PRD, scan this
index for overlapping scope: extend the existing PRD instead of creating a
near-duplicate.

| PRD | Scope |
|-----|-------|
| [api-latency-monitoring](api-latency-monitoring.md) | Owns privacy-safe server-boundary latency capture and bounded raw/hourly/daily evidence for y-agent API routes, plus the API Latency overview and route drill-down inside the extensible `monitor` module. |
| [bot-config-detail-modal](bot-config-detail-modal.md) | Owns the Bot viewer Config-tab detail interaction: open a bot's editor in a modal with standard dismissal, and always seed/refresh editable fields from the authoritative per-bot config payload with cache invalidation on write. |
| [bot-routing](bot-routing.md) | Routes each dispatched session to a bot via unified filters (bot name, backend, tier) intersected over the config pool: one candidate is used directly, several are weighted-drawn, and no filters or an empty result falls back to tier2 (never a skill-derived tier); a documented tier-role policy (tier2 default, tier1 judgment work, tier0 user escalation only, tier3 cheap volume) governs tier requests. |
| [bot-usage](bot-usage.md) | Owns bot-page usage visibility: durable per-model spend analytics (metered through the relay) plus current Claude / GPT (Codex) / Grok subscription limit-window status read directly from each provider, including the read-through lifecycle of the vendor CLIs' own credential files. |
| [chat-core](chat-core.md) | Owns the durable chat conversation model and its lifecycle across all surfaces: GUI chat list/detail/send, CLI dispatch (`y chat -m` fire-and-forget vs `--wait`) and REPL, and the persist-enqueue-run-stream pipeline (API → queue → worker → backend subprocess → message stream). |
| [chat-steer](chat-steer.md) | Delivers user messages sent to a chat mid-turn into the already-running agent session exactly once, without spawning a duplicate worker, across backends that accept live input and those that must be killed and resumed. |
| [cli-file-transfer](cli-file-transfer.md) | Owns bidirectional Mac↔EC2 file transfer in the `y` CLI under `y file upload` / `y file download`: rsync over SSH, API default-host resolution, dry-run/mirror/checksum/exclude, no personal inventory in the public surface. |
| [design-language](design-language.md) | Documents y-agent's Solarized Light and Dark visual language and the settled control conventions (4px radius, `shadow-float`, host classes `.y-check` / `.y-field`) in a self-contained, previewable reference. |
| [english-correction](english-correction.md) | Owns automatic, hourly, routine-driven grammar correction of the user's own chat prose: eligibility filtering (skip non-English, non-prose, and cross-skill dispatch messages), a durable per-correction error history with categories and dismiss, and a standalone read panel — decoupled from the live chat pipeline. |
| [filetree-navigation-state](filetree-navigation-state.md) | Owns authenticated File sidebar continuity across activity switches, refreshes, browser restarts, and devices: isolated per-panel/VM/work-directory expansion, selection, loaded branches, and scroll persisted through the owner-scoped backend preference store and safely reconciled with filesystem changes. |
| [module-system](module-system.md) | Owns the module as a versioned, self-contained domain shipped outside the deploy pipeline: one VM directory holding a domain's entities, repositories, migrations, API routes, CLI commands, logic, and UI, loaded in-process by the API behind a per-version sub-app and by the CLI from local source, with one atomic version spanning the published API and UI halves, one owner per table, and hand-applied migrations guarded by a publish-time schema preflight; absorbs `y ui` into `y module` and takes finance as the reference migration. |
| [public-module-demos](public-module-demos.md) | Owns the single `/demo` full-shell unauthenticated read-only demo application with in-shell switching among showcased surfaces, reproducing signed-in navigation while composing active production module UI over deterministic fictional fixtures and a restricted local command boundary, never real data or anonymous backend dispatch. |
| [session-tree-recovery](session-tree-recovery.md) | Owns recovery of frozen branches of the recursive session tree: persisted parent→child dispatch edges, a suppressor-based classifier that separates legitimately quiet work from missing callbacks / execution failures / stalls, a bounded scheduled recovery ladder that reports upward without ever re-running a child, accept-time trace and parent-ownership validation with quarantine for misrouted callbacks, and a CLI operator surface. |
| [todo-detail-view](todo-detail-view.md) | Owns how a single todo's detail/trace is reached, presented, and left in the authenticated app: an in-place Todo Detail viewer inside the Todo full view following the Finance full-view / Ticker Detail pattern, list-state-preserving back navigation and reload restoration, one authoritative todo-detail implementation instead of a module-local copy, and the intentional retirement of the standalone `trace.md` tab and its entry points. |
| [ui-dynamic-artifacts](ui-dynamic-artifacts.md) | Owns the browser-side runtime contract for UI that ships outside the application bundle: TSX built into immutable, content-hashed ES modules, loaded at runtime as real React panels against the versioned `@y/host` SDK, with per-panel failure isolation and instantaneous pointer-move rollback. Identity, versioning, publish, and the CLI surface pass to [module-system](module-system.md), which folds `y ui` into `y module`. |
| [xai-inline-search](xai-inline-search.md) | Owns one-shot native xAI web and X search after backend selection: explicit `xai_web` / `xai_x` source modes, Responses API request and parser behavior, citation transport, bounded empty-result retry, and the shared inline completion/failure lifecycle. |
